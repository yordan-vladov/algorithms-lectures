## Мотивация

- Как бихме търсили елемент в масив възможно най-бързо?
- Линейно търсене проверява елементите един по един - O(n)
- Ако масивът е **сортиран**, можем да отхвърляме половината от него на всяка стъпка
- Идея: сравняваме търсения елемент със средния елемент и стесняваме диапазона

```
[1, 3, 5, 7, 9, 11, 13]   търсим: 11
```

---

## Какво е Binary Search?

- **Binary Search** търси елемент в **сортиран** масив
- Сравнява търсената стойност със **средния** елемент
- Ако съвпадат - намерихме елемента
- Ако търсената стойност е **по-малка** - продължаваме в лявата половина
- Ако е **по-голяма** - продължаваме в дясната половина
- Повтаряме, докато намерим елемента или диапазонът се изпразни

---

## Принцип на работа

```
[1, 3, 5, 7, 9, 11, 13]   търсим: 11

low = 0, high = 6, mid = 3 → arr[3] = 7    7 < 11  → търсим вдясно
low = 4, high = 6, mid = 5 → arr[5] = 11   11 == 11 → намерен на индекс 5
```

- На всяка стъпка диапазонът на търсене се **намалява наполовина**
- За масив от `n` елемента са нужни най-много `log2(n)` стъпки

---

## Изисквания за прилагане

- Масивът трябва да е **сортиран** (възходящо или низходящо)
- Достъп до произволен елемент по индекс за **O(1)** (масив/vector, не свързан списък)
- Ако масивът не е сортиран - трябва първо да го сортираме, или Binary Search не работи коректно

---

## Псевдокод

```
low = 0, high = n - 1

докато low <= high:
    mid = low + (high - low) / 2
    ако arr[mid] == target:
        връщаме mid
    иначе ако arr[mid] < target:
        low = mid + 1
    иначе:
        high = mid - 1

връщаме -1   // не е намерен
```

- `mid = low + (high - low) / 2` вместо `(low + high) / 2` - избягва препълване (overflow)

---

## Примерна имплементация на C++ (итеративна)

```cpp
#include <iostream>
#include <vector>
using namespace std;

int binarySearch(const vector<int>& arr, int target) {
    int low = 0, high = arr.size() - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) low = mid + 1;
        else high = mid - 1;
    }

    return -1; // не е намерен
}
```

*(пълният код е във `binary_search.cpp`)*

## Рекурсивна имплементация

```cpp
int binarySearchRecursive(const vector<int>& arr, int target, int low, int high) {
    if (low > high) return -1;

    int mid = low + (high - low) / 2;

    if (arr[mid] == target) return mid;
    else if (arr[mid] < target) return binarySearchRecursive(arr, target, mid + 1, high);
    else return binarySearchRecursive(arr, target, low, mid - 1);
}
```

- Всяко рекурсивно извикване стеснява диапазона наполовина
- Изисква стек памет за рекурсията - **O(log n)**

---

## Пример за употреба

```cpp
int main() {
    vector<int> arr = {1, 3, 5, 7, 9, 11, 13};

    cout << binarySearch(arr, 11) << "\n"; // Изход: 5
    cout << binarySearch(arr, 4) << "\n";  // Изход: -1
}
```

## Сложност във времето

| Случай     | Сложност  | Кога се случва                          |
| ---------- | --------- | ---------------------------------------- |
| Най-добър  | O(1)      | Търсеният елемент е точно средният       |
| Среден     | O(log n)  | Обичайният случай                        |
| Най-лош    | O(log n)  | Елементът липсва или е в края на диапазона |

- Драстично по-бърз от линейното търсене (O(n)) за големи масиви

---

## Сложност по памет

- Итеративна версия: **O(1)** - не се нуждае от допълнителна памет
- Рекурсивна версия: **O(log n)** - памет за стека на рекурсивните извиквания

---

## Предимства на Binary Search

- **Много бърз** - O(log n) вместо O(n)
- Прост принцип - "разделяй и владей" върху диапазон от индекси
- Итеративната версия е **in-place** - O(1) памет

---

## Недостатъци на Binary Search

- Изисква масивът да е **сортиран** предварително
- Не работи ефективно върху структури без бърз достъп по индекс (напр. свързан списък)
- Сортирането преди търсене може да струва O(n log n), ако данните се променят често

---

## Кога да използваме Binary Search?

- Когато данните са **сортирани** и се търсят **много пъти** (търсенето е по-често от промените)
- Търсене в масиви, речници, таблици с диапазони
- Основа за много други алгоритми - напр. търсене на граница/първо срещане на условие

## Обобщение

- Binary Search търси елемент в **сортиран** масив, стеснявайки диапазона наполовина всеки път
- Сложност **O(log n)** във времето - много по-бърз от линейното търсене
- Памет: **O(1)** итеративно, **O(log n)** рекурсивно
- Изисква предварително сортирани данни и достъп по индекс за O(1)
