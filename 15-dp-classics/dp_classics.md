# Класически задачи с динамично програмиране

---

## Какво ще научим днес?

- Coin Change - минимален брой монети за дадена сума
- Longest Increasing Subsequence (LIS) - най-дълга растяща подредица
- Edit Distance (разстояние на Левенщайн) - най-малко операции за трансформация на низ
- Как да разпознаваме "формата" на DP таблицата - 1D срещу 2D
- Възстановяване на самото решение, не само оптималната стойност

---

## Мотивация

- В `14-dynamic-programming` видяхме общия шаблон: overlapping subproblems + optimal substructure → memoization/tabulation
- Fibonacci, Knapsack и LCS показаха как изглежда DP на практика
- Днес разглеждаме още три класически задачи, които се срещат постоянно - в изпити, интервюта и реални приложения
- Целта не е да запомните всяко решение наизуст, а да разпознаете **сигналите**, които водят до конкретната DP форма

```
Coin Change → 1D таблица, dp[сума]
LIS         → 1D таблица, dp[индекс]
Edit Distance → 2D таблица, dp[i][j] (двa низа - като LCS)
```

## Задача 1 - Coin Change (минимален брой монети)

**Задача:** дадени монети с определени стойности (неограничен брой от всяка) и сума `S`. Намерете **минималния** брой монети, с които се съставя точно `S`. Ако е невъзможно - върнете -1.

```
Монети: {1, 3, 4}     Сума: 6

Възможности:
  1+1+1+1+1+1 → 6 монети
  3+3         → 2 монети   ← оптимално
  4+1+1       → 3 монети
```

---

## Coin Change - структура на подпроблема

```
dp[s] = минимален брой монети за сума s

За всяка монета c:
  ако c <= s:  dp[s] = min(dp[s], dp[s - c] + 1)

dp[0] = 0   (нулева сума - 0 монети)
dp[s] = infinity, ако не съществува комбинация
```

```cpp
int coinChange(vector<int>& coins, int amount) {
    vector<int> dp(amount + 1, INT_MAX);
    dp[0] = 0;

    for (int s = 1; s <= amount; s++) {
        for (int c : coins) {
            if (c <= s && dp[s - c] != INT_MAX)
                dp[s] = min(dp[s], dp[s - c] + 1);
        }
    }

    return dp[amount] == INT_MAX ? -1 : dp[amount];
}
```

---

## Coin Change - визуализация на таблицата

```
Монети: {1, 3, 4}

s:     0  1  2  3  4  5  6
dp[s]: 0  1  2  1  1  2  2

dp[6]: пробваме монета 1 → dp[5]+1 = 3
       пробваме монета 3 → dp[3]+1 = 2   ← по-добро
       пробваме монета 4 → dp[2]+1 = 3
       dp[6] = min(3, 2, 3) = 2  ✓ (3+3)
```

- За всяка сума `s` пробваме **всяка** монета и вземаме най-добрия резултат от `s - монета`

## Задача 2 - Longest Increasing Subsequence (LIS)

**Задача:** намерете дължината на най-дългата **строго растяща** подредица (не задължително последователна) в масив.

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]

Растящи подредици:
  [10]                  → дължина 1
  [2, 5, 7, 101]        → дължина 4
  [2, 3, 7, 101]        → дължина 4   ← едно от оптималните
  [2, 3, 7, 18]         → дължина 4   ← също оптимално

LIS дължина = 4
```

---

## LIS - структура на подпроблема (O(n²))

```
dp[i] = дължината на най-дългата растяща подредица, ЗАВЪРШВАЩА точно на индекс i

За всеки j < i:
  ако nums[j] < nums[i]:  dp[i] = max(dp[i], dp[j] + 1)

Отговорът = max(dp[i]) за всички i  (не задължително последният елемент)
```

```cpp
int lengthOfLIS(vector<int>& nums) {
    int n = nums.size();
    vector<int> dp(n, 1);   // всеки елемент сам по себе си е подредица с дължина 1

    int best = 1;
    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i])
                dp[i] = max(dp[i], dp[j] + 1);
        }
        best = max(best, dp[i]);
    }

    return best;
}
```

---

## LIS - визуализация на таблицата

```
nums: [10,  9,  2,  5,  3,  7, 101, 18]
dp:   [ 1,  1,  1,  2,  2,  3,   4,  4]
                       ↑           ↑
              5 продължава [2]  101 продължава [2,5,7] или [2,3,7]

dp[5]=3: nums[5]=7, проверяваме j=0..4
  nums[2]=2 < 7 → dp[2]+1 = 2
  nums[3]=5 < 7 → dp[3]+1 = 3   ← най-добро
  nums[4]=3 < 7 → dp[4]+1 = 3

max(dp) = 4  → отговорът
```

- O(n²) е достатъчно за курса; съществува и O(n log n) вариант с binary search върху помощен масив (извън обхвата днес)

## Задача 3 - Edit Distance (разстояние на Левенщайн)

**Задача:** дадени два низа. Намерете минималния брой операции (вмъкване, изтриване, замяна на символ), за да превърнем единия низ в другия.

```
word1 = "horse"    word2 = "ros"

horse → rorse   (замени 'h' с 'r')
rorse → rose    (изтрий 'r')
rose  → ros     (изтрий 'e')

Edit Distance = 3
```

---

## Edit Distance - структура на подпроблема

- Прилича на LCS от `14-dynamic-programming`, но вместо да броим **съвпадения**, броим **операции**

```
dp[i][j] = минимален брой операции да превърнем
           първите i символа на word1 в първите j символа на word2

Ако word1[i-1] == word2[j-1]:
    dp[i][j] = dp[i-1][j-1]                         // символите съвпадат, нищо не правим

Иначе - вземаме най-добрата от трите операции:
    dp[i][j] = 1 + min(
        dp[i-1][j],      // изтриване от word1
        dp[i][j-1],      // вмъкване в word1
        dp[i-1][j-1]     // замяна
    )
```

```cpp
int editDistance(string word1, string word2) {
    int n = word1.size(), m = word2.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));

    for (int i = 0; i <= n; i++) dp[i][0] = i;   // изтриваме всички i символа
    for (int j = 0; j <= m; j++) dp[0][j] = j;   // вмъкваме всички j символа

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (word1[i - 1] == word2[j - 1])
                dp[i][j] = dp[i - 1][j - 1];
            else
                dp[i][j] = 1 + min({dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1]});
        }
    }

    return dp[n][m];
}
```

---

## Edit Distance - визуализация на таблицата

```
word1 = "horse"   word2 = "ros"

        ""  r  o  s
    ""   0  1  2  3
    h    1  1  2  3
    o    2  2  1  2
    r    3  2  2  2
    s    4  3  3  2
    e    5  4  4  3

dp[5][3] = 3  ← отговорът
```

- Базовите редове/колони (`dp[i][0] = i`, `dp[0][j] = j`) означават "трансформирай към празен низ = изтрий всичко"

## Сложност

| Задача              | Форма на dp    | Сложност       |
| --------------------- | ---------------- | ---------------- |
| Coin Change            | 1D, dp[сума]     | O(сума · брой монети) |
| LIS (O(n²) вариант)    | 1D, dp[индекс]   | O(n²)             |
| Edit Distance          | 2D, dp[i][j]     | O(n · m)          |

---

## Как да разпознаем формата на таблицата?

```
Един низ / една поредица от числа, отговорът зависи от "докъде стигнахме"
  → 1D таблица:  dp[i]

Два низа / две поредици, сравняваме ги едно спрямо друго
  → 2D таблица:  dp[i][j]

Сума / капацитет / бюджет, за който трябва да "съставим" нещо
  → 1D таблица индексирана по самата сума:  dp[сума]
```

- Същите сигнали, които видяхме в `14-dynamic-programming`: "максимум/минимум/брой начини" + решение, зависещо от по-малки версии на проблема

---

## Възстановяване на решението (не само стойността)

- `dp[n][m]` дава само **дължината/стойността** - но често трябва самото решение (напр. самата LIS, не само `4`)
- Техника: **проследяваме таблицата назад**, като на всяка стъпка проверяваме коя избор е довел до текущата клетка

```
Edit Distance dp[5][3] = 3 → връщаме се назад:
  dp[5][3] от dp[4][2]+1 (word1[4]='e' изтрито)
  dp[4][2] от dp[3][2]   ('s'=='s' съвпадение)
  dp[3][2] от dp[2][1]+1 ('r' заменено)
  ...

Възстановена поредица от операции: замени h→r, изтрий r, изтрий e
```

- Същият принцип важи за LCS (бонус задачата от `14-dynamic-programming`) и за LIS

## Обобщение

- Coin Change показва 1D DP по сума - `dp[s] = min(dp[s], dp[s-c] + 1)` за всяка монета `c`
- LIS показва 1D DP по индекс - `dp[i]` зависи от всички по-малки `dp[j]` с `nums[j] < nums[i]`
- Edit Distance показва 2D DP върху два низа - подобна структура на LCS, но с три възможни операции вместо съвпадение
- Формата на таблицата (1D срещу 2D) следва директно от формата на входа - един низ/масив срещу два
- `dp[n][m]` дава оптималната **стойност**; самото решение се възстановява чрез проследяване назад по таблицата
