## Мотивация

- Вече знаем прости алгоритми за сортиране - Bubble Sort, Selection Sort
- Те работят, но са **O(n²)** - бавни за големи масиви
- Нужен ни е по-бърз подход

```
1 000 000 елемента:
  O(n²)      →  ~1 000 000 000 000 операции
  O(n log n) →  ~20 000 000 операции
```

- Quick Sort постига **средно O(n log n)**, като разделя проблема на по-малки части

---

## Какво е Quick Sort?

- **Quick Sort** е алгоритъм за сортиране от типа "разделяй и владей" (divide and conquer)
- Основна идея:
    1. Избираме елемент - **pivot**
    2. **Разделяме** масива - по-малките от pivot отляво, по-големите отдясно
    3. Рекурсивно сортираме двете части
- За разлика от Merge Sort - работи **на място** (in-place), не се нуждае от допълнителен масив

---

## Принцип на работа - "разделяй и владей"

```
Големият проблем:      Сортирай [10, 7, 8, 9, 1, 5]

Раздели:                избери pivot → раздели на "по-малки" и "по-големи"

По-малки от pivot:      Сортирай ги (рекурсивно)
По-големи от pivot:     Сортирай ги (рекурсивно)

Владей:                 съедини резултатите - масивът вече е сортиран
```

- Базов случай: масив с 0 или 1 елемент - вече е сортиран

---

## Стъпка 1 - Избор на pivot

- Избираме елемент от масива - **pivot**
- Най-прост избор: последният елемент

```
[10, 7, 8, 9, 1, 5]
                 ↑
              pivot = 5
```

- По-нататък ще видим защо изборът на pivot е важен

---

## Стъпка 2 - Partition (разделяне)

- Пренареждаме масива така, че:
  - Елементите **по-малки** от pivot са отляво
  - Елементите **по-големи** от pivot са отдясно
  - Pivot застава на **своята финална позиция**

```
Преди:  [10, 7, 8, 9, 1, 5]

След partition (pivot = 5):

        [1, 5, 8, 9, 10, 7]
             ↑
     pivot на позиция 1
     (всичко вляво < 5, всичко вдясно > 5)
```

---

## Стъпка 3 - Рекурсия

- След partition, pivot е на правилното си място
- Рекурсивно прилагаме Quick Sort върху **лявата** и **дясната** част

```
        [1, 5, 8, 9, 10, 7]
         │  │  └───────────┘
         │  │   сортирай тази част
         │  └── на място
         └───── сортирай тази част (тук е само 1 елемент)
```

- Рекурсията спира, когато частта има 0 или 1 елемент

---

## Lomuto partition - алгоритъм

- Най-разпространената схема за partition
- Избираме `arr[high]` за pivot
- Пазим индекс `i` - границата на елементите, по-малки от pivot

```
i = low - 1

за j от low до high - 1:
    ако arr[j] < pivot:
        i++
        swap(arr[i], arr[j])

swap(arr[i + 1], arr[high])   // поставяме pivot на мястото му
return i + 1                  // финалната позиция на pivot
```

---

## Lomuto partition - визуализация

```
arr = [10, 7, 8, 9, 1, 5]   pivot = 5,  i = -1

j=0: arr[0]=10  не е < 5              → [10, 7, 8, 9, 1, 5]
j=1: arr[1]=7   не е < 5              → [10, 7, 8, 9, 1, 5]
j=2: arr[2]=8   не е < 5              → [10, 7, 8, 9, 1, 5]
j=3: arr[3]=9   не е < 5              → [10, 7, 8, 9, 1, 5]
j=4: arr[4]=1   < 5 → i=0, swap(0,4)  → [1, 7, 8, 9, 10, 5]

swap(i+1, high) → swap(1, 5)          → [1, 5, 8, 9, 10, 7]

връща i + 1 = 1  (позицията на pivot)
```

---

## Примерна имплементация на C++

```cpp
#include <iostream>
#include <vector>
using namespace std;

int partition(vector<int>& arr, int low, int high) {
    // избираме последния елемент за pivot
    int pivot = arr[high];

    // i сочи края на "по-малката от pivot" зона
    int i = low - 1;

    for (int j = low; j <= high - 1; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr[i], arr[j]);
        }
    }

    // поставяме pivot на неговата финална позиция
    swap(arr[i + 1], arr[high]);
    return i + 1;
}
```

## Примерна имплементация - рекурсията

```cpp
void quickSort(vector<int>& arr, int low, int high) {
    if (low < high) {
        // pi е финалната позиция на pivot
        int pi = partition(arr, low, high);

        // рекурсия за елементите вляво и вдясно от pivot
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

int main() {
    vector<int> arr = {10, 7, 8, 9, 1, 5};
    quickSort(arr, 0, arr.size() - 1);

    for (int x : arr) cout << x << " ";
    // Изход: 1 5 7 8 9 10
}
```

*(пълният код е във `quick_sort.cpp`)*

## Дърво на рекурсията

```
                quickSort([10,7,8,9,1,5])
                     pivot = 5, pi = 1
                    /                  \
        quickSort([1])          quickSort([8,9,10,7])
        (базов случай)                pivot = 7, pi = 2
                                    /              \
                          quickSort([])     quickSort([9,10])
                                                pivot=10, pi=1
                                              /            \
                                    quickSort([9])   quickSort([])
```

- Всяко ниво прави partition - масивът се "събира" сортиран отдолу нагоре

---

## Защо изборът на pivot е важен?

- Ако pivot винаги дели масива **на две равни части** → дълбочина на рекурсията `O(log n)`
- Ако pivot винаги е **най-малкият или най-големият** елемент → дълбочина `O(n)` (влошен случай)

```
Добро разделяне (сортиран наполовина):
        n → n/2 → n/4 → ... → 1        дълбочина O(log n)

Лошо разделяне (вече сортиран масив, pivot = последен):
        n → n-1 → n-2 → ... → 1        дълбочина O(n)
```

- Затова изборът на pivot влияе пряко на производителността

## Проблемен случай - вече сортиран масив

```
arr = [1, 2, 3, 4, 5],  pivot = arr[high] винаги последният

partition([1,2,3,4,5]) → pivot=5, всичко < 5 → pi = 4
partition([1,2,3,4])   → pivot=4, всичко < 4 → pi = 3
partition([1,2,3])     → pivot=3, всичко < 3 → pi = 2
...
```

- Всяко partition разделя масива на `n-1` и `0` елемента
- Рекурсията е дълбока колкото n → **O(n²)** в най-лошия случай

---

## Решение - случаен pivot

- Вместо винаги последния елемент, избираме **случаен** индекс за pivot
- Разменяме го с последната позиция и продължаваме както обичайно

```cpp
uniform_int_distribution<int> dist(low, high);
int randomIndex = dist(gen);

swap(arr[randomIndex], arr[high]);  // сега партиционираме нормално
```

- Прави влошения случай **статистически изключително малко вероятен**
- Виж `quick_sort_random_pivot.cpp`

---

## Hoare partition - алтернативна схема

- Използва **два показалеца**, които се движат един към друг
- Обикновено прави по-малко размени от Lomuto

```cpp
int i = low - 1, j = high + 1;

while (true) {
    do { i++; } while (arr[i] < pivot);
    do { j--; } while (arr[j] > pivot);

    if (i >= j) return j;
    swap(arr[i], arr[j]);
}
```

- Виж `quick_sort_hoare.cpp` - комбиниран със случаен pivot

---

## Итеративна версия

- Рекурсията използва call stack - можем да го направим **явно** с `std::stack`
- Избягва риска от stack overflow при много дълбока рекурсия

```cpp
stack<pair<int,int>> st;
st.push({low, high});

while (!st.empty()) {
    auto [l, h] = st.top();
    st.pop();

    if (l < h) {
        int p = hoarePartition(arr, l, h);
        st.push({l, p});
        st.push({p + 1, h});
    }
}
```

- Виж `quick_sort_iterative.cpp`

## Сложност във времето

| Случай               | Сложност    | Кога се случва                          |
| --------------------- | ----------- | ---------------------------------------- |
| Най-добър             | O(n log n)  | Pivot винаги дели масива на две равни части |
| Среден                | O(n log n)  | Типично поведение при случайни данни     |
| Най-лош               | O(n²)       | Pivot винаги е най-малкият/най-големият елемент |

- Случайният pivot прави най-лошия случай практически невероятен

---

## Сложност по памет

- Сортира **на място** (in-place) - не се нуждае от копие на масива
- Но рекурсията заема памет в **call stack**

| Случай    | Дълбочина на рекурсията | Памет     |
| --------- | ------------------------ | --------- |
| Най-добър | O(log n)                 | O(log n)  |
| Най-лош   | O(n)                     | O(n)      |

---

## Предимства на Quick Sort

- **Бърз на практика** - средно O(n log n), с малка константа
- **In-place** - не изисква допълнителна памет за масив (само стека на рекурсията)
- **Кеш-приятелив** - работи последователно върху паметта
- Лесно се **паралелизира** - двете половини са независими

---

## Недостатъци на Quick Sort

- Най-лош случай **O(n²)** при лош избор на pivot
- **Нестабилен** - елементи с еднакви стойности могат да сменят относителния си ред
- Рекурсията може да доведе до **stack overflow** при лош pivot (дълбочина O(n))
- Чувствителен към избора на pivot - нужна е добра стратегия (random/median)

---

## Quick Sort срещу Merge Sort

| Характеристика     | Quick Sort              | Merge Sort           |
| ------------------- | ------------------------ | --------------------- |
| Среден случай       | O(n log n)               | O(n log n)            |
| Най-лош случай      | O(n²)                    | O(n log n)            |
| Памет                | O(log n) (in-place)      | O(n) (нужен е буфер)  |
| Стабилност           | Не                       | Да                    |
| На практика          | Обикновено по-бърз       | Предсказуем           |

---

## Кога да използваме Quick Sort?

- Когато данните са **достатъчно случайни** или използваме random/median pivot
- Когато паметта е **ограничена** - in-place сортиране
- Когато не ни е нужна **стабилност** на сортирането
- Стандартните библиотеки (`std::sort`) често използват хибрид - Quick Sort + Heap Sort (Introsort)

## Обобщение

- Quick Sort сортира чрез **разделяй и владей** - избор на pivot, partition, рекурсия
- Средна сложност **O(n log n)**, най-лош случай **O(n²)**
- Сортира **на място** - паметта е O(log n) в среден случай
- Не е стабилен, но е много бърз на практика
- Изборът на pivot (случаен, медиана) е ключов за избягване на влошения случай
