# Алгоритъм на Дийкстра

---

## Какво ще научим днес?

- Защо BFS не стига за претеглени графи
- Идеята зад алгоритъма на Dijkstra
- Имплементация на Dijkstra (O(V²))
- Реконструкция на най-късия път
- Кога Dijkstra **не работи** - отрицателни тегла
- Dijkstra срещу BFS и Prim

---

## Мотивация

- BFS намира най-късия път по **брой ребра** - работи само за непретеглени графи
- В претеглен граф "най-малко спирки" не значи "най-евтин път"

```
0 —(10)— 1
 \               \
 (1)              (1)
   \               \
    2 —(1)— 3 —(1)— 1

BFS от 0 до 1: директно ребро 0—1, 1 спирка, тегло 10
Реален най-евтин път: 0→2→3→1, 3 спирки, тегло 3

BFS избира грешния път - трябва ни алгоритъм, който брои тегла, не ребра
```

- **Dijkstra** намира най-евтиния път от един връх до всички останали в претеглен граф **без отрицателни тегла**

---

## Идея на алгоритъма

- Пази `dist[v]` - засега най-малкото известно тегло от `start` до `v`
- На всяка стъпка избира **непосетения** връх с най-малко `dist[]` и го "финализира"
- От него **релаксира** (обновява) съседите си, ако е намерен по-евтин път през него

```
Граф:  0—1(4), 0—2(1), 1—2(2), 1—3(5), 2—3(8), 2—4(10), 3—4(2)
Dijkstra от 0:

  dist: [0, ∞, ∞, ∞, ∞]
  обработи 0 → dist: [0, 4, 1, ∞, ∞]
  обработи 2 (най-малко) → през 2: dist[1]=min(4,1+2)=3, dist[3]=1+8=9, dist[4]=1+10=11
  обработи 1 (dist=3) → през 1: dist[3]=min(9,3+5)=8
  обработи 3 (dist=8) → през 3: dist[4]=min(11,8+2)=10
  обработи 4 (dist=10) → край

  Резултат: dist = [0, 3, 1, 8, 10]
```

- Забележете как `dist[1]` се подобрява от 4 на 3, след като намираме по-евтин път през 2

## Имплементация на Dijkstra (O(V²))

```cpp
#include <vector>
#include <climits>
using namespace std;
const int INF = INT_MAX;

vector<int> dijkstra(int start, int n, vector<vector<int>>& graph) {
    vector<int> dist(n, INF);
    vector<bool> visited(n, false);
    dist[start] = 0;

    for (int i = 0; i < n; i++) {
        int u = -1;
        for (int v = 0; v < n; v++)                // намери най-близкия непосетен
            if (!visited[v] && (u == -1 || dist[v] < dist[u]))
                u = v;

        if (dist[u] == INF) break;                  // остатъкът е недостижим
        visited[u] = true;

        for (int v = 0; v < n; v++)                 // релаксация на съседите
            if (graph[u][v] && dist[u] + graph[u][v] < dist[v])
                dist[v] = dist[u] + graph[u][v];
    }
    return dist;
}
```

- Забележете колко прилича на `primMST` от миналата лекция - разликата е **какво пазим** в `dist[]` (общо разстояние до `start`, не тегло на едно ребро) - по-късно (лекция за heap) `priority_queue` ускорява това до O(E log V)

## Реконструкция на най-късия път

```cpp
vector<int> dijkstraPath(int start, int end, int n, vector<vector<int>>& graph) {
    vector<int> dist(n, INF), parent(n, -1);
    vector<bool> visited(n, false);
    dist[start] = 0;

    for (int i = 0; i < n; i++) {
        int u = -1;
        for (int v = 0; v < n; v++)
            if (!visited[v] && (u == -1 || dist[v] < dist[u]))
                u = v;
        if (dist[u] == INF) break;
        visited[u] = true;

        for (int v = 0; v < n; v++)
            if (graph[u][v] && dist[u] + graph[u][v] < dist[v]) {
                dist[v] = dist[u] + graph[u][v];
                parent[v] = u;
            }
    }

    vector<int> path;
    for (int at = end; at != -1; at = parent[at])
        path.push_back(at);
    reverse(path.begin(), path.end());
    return path;   // {} ако parent[end] остане -1 и end != start
}
```

- Същият трик като при BFS - `parent[]` позволява да минем пътя назад от `end` до `start`

## Защо Dijkstra не работи с отрицателни тегла

```
Граф:  0—1(4), 0—2(5), 1—2(-3)

Dijkstra от 0:
  обработи 0 → dist: [0, 4, 5]
  обработи 1 (най-малко, dist=4) → през 1: dist[2] = min(5, 4-3) = 1
  обработи 2 (вече "финализиран" преди update-а!) → dist[2] остава грешно голямо

Проблем: Dijkstra финализира връх веднага щом стане "най-близкият" -
         но отрицателно ребро може по-късно да намали разстоянието му
```

- За графи с отрицателни тегла се използва **Bellman-Ford** (извън обхвата на тази лекция)

---

## Dijkstra срещу BFS срещу Prim

| Характеристика       | BFS                    | Dijkstra                     | Prim                          |
| ---------------------- | ----------------------- | ------------------------------ | ------------------------------- |
| Намира                | Най-малко ребра          | Най-евтин път от `start`       | Минимално покриващо дърво       |
| Тип граф               | Непретеглен              | Претеглен, без отриц. тегла    | Претеглен                       |
| Структура               | `queue`                  | `dist[]` + минимум (или heap)  | `dist[]` + минимум (или heap)   |
| Какво пази `dist[v]`   | Брой ребра до `v`        | Тегло на пътя `start → v`      | Тегло на **едно** ребро до дървото |
| Сложност                | O(V + E)                 | O(V²) (или O(E log V) с heap)  | O(V²) (или O(E log V) с heap)   |

## Реални приложения

- **GPS навигация** - най-бърз/най-къс маршрут между два адреса
- **Мрежово маршрутизиране** - протоколи като OSPF намират най-евтин път за пакети

- **Планиране на полети** - най-евтина комбинация от прекачвания по цена/време

## Обобщение

- **Dijkstra** намира най-евтиния път от един връх до всички останали в претеглен граф без отрицателни тегла
- Работи като Prim, но пази **общо разстояние** до `start`, не тегло на едно ребро
- `dist[]` + релаксация на съседите на всяка стъпка; O(V²) без heap, O(E log V) с `priority_queue`
- Не работи с отрицателни тегла - за тях се използва Bellman-Ford
- BFS → най-малко ребра; **Dijkstra** → най-евтин път; **Prim/Kruskal** → минимално покриващо дърво
