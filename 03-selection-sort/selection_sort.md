## Мотивация

- При Bubble Sort правим много размени - на всяка крачка, при нужда
- Може ли да намалим броя размени?
- Идея: намираме **директно** най-малкия елемент и го поставяме на място - **една** размяна на обхождане

---

## Какво е Selection Sort?

- **Selection Sort** разделя масива на две части:
  - **Сортирана** част (в началото, първоначално празна)
  - **Несортирана** част (остатъкът)
- На всяка стъпка:
  1. Намира **най-малкия** елемент в несортираната част
  2. Разменя го с първия елемент на несортираната част
  3. Границата между двете части се измества с едно място напред

---

## Принцип на работа - визуализация

```
[10, 7, 8, 9, 1, 5]
 └────── несортирана ──────┘

Стъпка 1: минимум = 1 (индекс 4) → размяна с индекс 0
[1, 7, 8, 9, 10, 5]
 └┘  └──── несортирана ────┘

Стъпка 2: минимум = 5 (индекс 5) → размяна с индекс 1
[1, 5, 8, 9, 10, 7]
 └───┘  └─── несортирана ───┘
```

---

## Принцип на работа - продължение

```
Стъпка 3: минимум = 7 (индекс 5) → размяна с индекс 2
[1, 5, 7, 9, 10, 8]

Стъпка 4: минимум = 8 (индекс 5) → размяна с индекс 3
[1, 5, 7, 8, 10, 9]

Стъпка 5: минимум = 9 (индекс 5) → размяна с индекс 4
[1, 5, 7, 8, 9, 10]     ← сортиран!
```

- За разлика от Bubble Sort - точно **една** размяна на обхождане

---

## Псевдокод

```
за i от 0 до n - 2:
    minIndex = i

    за j от i + 1 до n - 1:
        ако arr[j] < arr[minIndex]:
            minIndex = j

    swap(arr[i], arr[minIndex])
```

- Външният цикъл - граница между сортирана/несортирана част
- Вътрешният цикъл - търсене на минимума в несортираната част

---

## Примерна имплементация на C++

```cpp
#include <iostream>
#include <vector>
using namespace std;

void selectionSort(vector<int>& arr) {
    int n = arr.size();

    for (int i = 0; i < n - 1; i++) {
        // намираме индекса на най-малкия елемент
        int minIndex = i;

        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }

        // разменяме го с първия елемент на несортираната част
        if (minIndex != i) {
            swap(arr[i], arr[minIndex]);
        }
    }
}
```

*(пълният код е във `selection_sort.cpp`)*

## Пример за употреба

```cpp
int main() {
    vector<int> arr = {10, 7, 8, 9, 1, 5};

    selectionSort(arr);

    for (int x : arr) cout << x << " ";
    // Изход: 1 5 7 8 9 10
}
```

## Сложност във времето

| Случай     | Сложност | Бележка                                   |
| ---------- | -------- | ------------------------------------------ |
| Най-добър  | O(n²)    | Броят сравнения не зависи от подредбата    |
| Среден     | O(n²)    | Винаги обхождаме цялата несортирана част   |
| Най-лош    | O(n²)    | Няма ранно спиране, за разлика от Bubble Sort |

- За разлика от Bubble Sort - **няма подобрение** дори при вече сортиран масив

---

## Сложност по памет

- Сортира **на място** (in-place)
- Памет: **O(1)**

---

## Брой размени - предимство пред Bubble Sort

| Алгоритъм       | Брой сравнения | Брой размени (най-лош случай) |
| ---------------- | -------------- | ------------------------------ |
| Bubble Sort      | O(n²)          | O(n²)                          |
| Selection Sort   | O(n²)          | O(n) - точно n-1 размени       |

- Полезно, когато **записът в паметта е скъп** операция (напр. флаш памет, EEPROM)

---

## Предимства на Selection Sort

- **Прост** за разбиране и имплементация
- **Минимален брой размени** - точно `n - 1` в най-лошия случай
- **In-place** - памет O(1)
- Полезен, когато записът е по-скъп от сравнението

---

## Недостатъци на Selection Sort

- **Бавен** - винаги O(n²), дори при сортиран масив
- **Нестабилен** в стандартната имплементация - размяната може да промени реда на еднакви елементи
- Няма механизъм за ранно спиране, за разлика от Bubble Sort

---

## Selection Sort срещу Bubble Sort

| Характеристика      | Selection Sort         | Bubble Sort                |
| -------------------- | ------------------------ | ---------------------------- |
| Сложност             | винаги O(n²)             | O(n) до O(n²) (с оптимизация) |
| Брой размени         | O(n) - малко             | O(n²) - много                |
| Стабилност           | Не (в стандартния вариант) | Да                          |
| Кога е по-добър      | Когато записът е скъп     | Когато данните са почти сортирани |

---

## Кога да използваме Selection Sort?

- Когато **записът в паметта** е скъпа операция, а сравненията - евтини
- При **малки** масиви, за учебни цели
- Не се препоръчва при големи набори от данни - има по-ефективни алгоритми (O(n log n))

## Обобщение

- Selection Sort намира минимума в несортираната част и го поставя на място
- Сложност **O(n²)** във всички случаи - без ранно спиране
- Прави **минимален брой размени** - `n - 1`
- Прост, in-place, но нестабилен и неефективен за големи данни
