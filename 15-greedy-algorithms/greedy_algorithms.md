# Жадни алгоритми (Greedy Algorithms)

---

## Какво ще научим днес?

- Какво е жаден алгоритъм - локално оптимален избор на всяка стъпка
- Пример: Смяна на монети (кога greedy работи, кога не)
- Пример: Избор на дейности (Activity Selection)
- Пример: Дробна раница (Fractional Knapsack) - контраст с 0/1 Knapsack от миналия урок
- Кога жадният подход дава оптимално решение

---

## Мотивация

- В `14-dynamic-programming` решихме 0/1 Knapsack, разглеждайки **всички** комбинации чрез таблица
- Понякога не ни трябва толкова работа - **прост, "лаком" избор на всяка стъпка** дава оптималния отговор
- **Пример:** връщане на ресто от 67 лв с банкноти 50, 20, 10, 5, 1

```
Жадно:  вземи най-голямата банкнота, която "събира" се в остатъка
  67 → 50 (остават 17) → 10 (остават 7) → 5 (остават 2) → 1, 1
  Резултат: 50 + 10 + 5 + 1 + 1 = 4 банкноти
```

- Не се налага да разглеждаме всички комбинации - жадният избор е достатъчен **тук**

---

## Какво е жаден алгоритъм?

- На всяка стъпка правим **локално най-добрия** избор, без да преразглеждаме предишни решения
- Никога не се връщаме назад (за разлика от backtracking) и не пазим таблица с подпроблеми (за разлика от DP)

```
Общ шаблон:

greedy(проблем):
    решение = []
    докато проблемът не е решен:
        избери НАЙ-ДОБРИЯ достъпен избор в момента (по някакъв критерий)
        добави го към решението
    върни решение
```

- **Внимание:** локално най-добрият избор не винаги води до глобално най-добро решение!

## Пример 1 - Смяна на монети

```cpp
vector<int> makeChange(vector<int>& coins, int amount) {
    // coins трябва да е сортиран низходящо
    vector<int> result;

    for (int coin : coins) {
        while (amount >= coin) {
            amount -= coin;
            result.push_back(coin);
        }
    }

    return result;  // празен, ако amount != 0 в края
}
```

```
coins = {50, 20, 10, 5, 1},  amount = 67

67 >= 50 → вземи 50, остават 17
17 <  50, 17 >= 20? не → 17 >= 10 → вземи 10, остават 7
 7 >= 5  → вземи 5, остават 2
 2 >= 1  → вземи 1, остават 1
 1 >= 1  → вземи 1, остават 0

Резултат: [50, 10, 5, 1, 1] → 4 монети
```

---

## Когато greedy за монети НЕ работи

```
coins = {1, 3, 4},  amount = 6

Жадно:  6 >= 4 → вземи 4 (остават 2) → 2 >= 1 → вземи 1, 1
        Резултат: [4, 1, 1] → 3 монети

Оптимално (DP от миналия урок): [3, 3] → 2 монети!
```

- Жадният избор на "най-голямата монета" **не е винаги правилен** - зависи от **системата монети**
- Стандартните валути (1, 5, 10, 20, 50...) са проектирани да работят с greedy - но не всяка система е такава
- Затова Coin Change в общия случай се решава с **DP**, не с greedy (виж домашното от `14-dynamic-programming`)

## Пример 2 - Избор на дейности (Activity Selection)

**Задача:** имате N дейности с начало и край. Изберете максимален брой дейности, които **не се припокриват** във времето.

```
Дейности (начало, край):
  A(1,4)  B(3,5)  C(0,6)  D(5,7)  E(3,9)  F(5,9)  G(6,10)  H(8,11)  I(8,12)  J(2,14)

Оптимален избор: A(1,4), D(5,7), H(8,11)  → 3 дейности
```

---

## Activity Selection - жадна стратегия

- Ключова идея: **сортирай по край**, после винаги избирай следващата дейност, чието начало >= края на последната избрана

```cpp
struct Activity { int start, end; };

int activitySelection(vector<Activity>& activities) {
    sort(activities.begin(), activities.end(),
         [](Activity& a, Activity& b) { return a.end < b.end; });

    int count = 1;
    int lastEnd = activities[0].end;

    for (int i = 1; i < activities.size(); i++) {
        if (activities[i].start >= lastEnd) {
            count++;
            lastEnd = activities[i].end;
        }
    }

    return count;
}
```

---

## Activity Selection - защо работи?

```
Сортирани по край: A(1,4)  B(3,5)  C(0,6)  E(3,9)  D(5,7)  F(5,9)  G(6,10)  H(8,11)  I(8,12)

Избери A(1,4)  → last_end = 4
  B(3,5) start=3 < 4 → пропусни
  C(0,6) start=0 < 4 → пропусни
Избери D(5,7)  → start=5 >= 4 → last_end = 7
  F(5,9) start=5 < 7 → пропусни
  G(6,10) start=6 < 7 → пропусни
Избери H(8,11) → start=8 >= 7 → last_end = 11

Резултат: A, D, H → 3 дейности
```

- Дейността, която **свършва най-рано**, оставя най-много място за следващите - това е "жадният" критерий
- Доказва се формално с **exchange argument**: всяко оптимално решение може да се "размени" с жадното, без да намалее броят дейности

## Пример 3 - Дробна раница (Fractional Knapsack)

- В `14-dynamic-programming` видяхме 0/1 Knapsack - всеки предмет или изцяло, или не се взима
- Ако можем да вземаме **части** от предмет (напр. злато на прах, зърно) - жаден подход дава **оптимален** отговор

```
Предмети:  тегло: [10, 20, 30]   стойност: [60, 100, 120]
Капацитет: W = 50

стойност/тегло: 6.0, 5.0, 4.0
```

```cpp
struct Item { int weight, value; };

double fractionalKnapsack(vector<Item>& items, int capacity) {
    sort(items.begin(), items.end(), [](Item& a, Item& b) {
        return (double)a.value / a.weight > (double)b.value / b.weight;
    });

    double totalValue = 0;
    int remaining = capacity;

    for (auto& item : items) {
        if (item.weight <= remaining) {
            totalValue += item.value;          // вземи изцяло
            remaining -= item.weight;
        } else {
            totalValue += item.value * ((double)remaining / item.weight);  // вземи част
            break;
        }
    }

    return totalValue;
}
```

```
Сортирано по стойност/тегло: (10,60,6.0) (20,100,5.0) (30,120,4.0)

Вземи (10,60) изцяло  → remaining=40, стойност=60
Вземи (20,100) изцяло → remaining=20, стойност=160
Вземи 20/30 от (30,120) → стойност += 120*(20/30)=80 → общо 240

Резултат: 240
```

- За разлика от 0/1 Knapsack, тук **сортирането по стойност/тегло + жаден избор** е доказано оптимално

---

## 0/1 Knapsack срещу Fractional Knapsack

| Характеристика     | 0/1 Knapsack             | Fractional Knapsack      |
| --------------------- | ---------------------------- | ---------------------------- |
| Може ли да делим предмет? | Не                       | Да                            |
| Правилен подход        | Динамично програмиране (DP)  | Жаден (greedy)               |
| Защо greedy не работи за 0/1 | Локален избор може да блокира по-добра комбинация | N/A |
| Сложност                | O(n · W)                     | O(n log n) - само сортиране   |

---

## Кога жадният подход дава оптимално решение?

- Проблемът трябва да има **greedy choice property**: локално оптималният избор води до глобално оптимално решение
- Обикновено се доказва с:
    - **Exchange argument** - показваме, че всяко решение може да се "поправи" към жадното без да се влоши
    - **Matroid структура** (напреднала тема - извън обхвата на този курс)

```
Работи:    Activity Selection, Fractional Knapsack, свързване с минимално тегло (MST)
НЕ работи: 0/1 Knapsack, Coin Change с произволна система монети
```

- Ако не сте сигурни дали greedy работи - опитайте да намерите контрапример (както с монети {1,3,4})

---

## Greedy срещу Dynamic Programming

| Характеристика       | Greedy                          | Dynamic Programming              |
| ----------------------- | ----------------------------------- | ------------------------------------ |
| Разглежда всички възможности? | Не - само локално най-доброто | Да - систематично, чрез таблица     |
| Връща се назад?         | Никога                              | Не буквално, но комбинира подрешения |
| Скорост                 | Обикновено по-бърз                  | По-бавен (по-голяма таблица)         |
| Гаранция за оптималност | Само ако проблемът го позволява     | Винаги (ако DP е приложимо)          |

## Обобщение

- Жадните алгоритми правят **локално най-добрия избор** на всяка стъпка, без връщане назад
- Работят перфектно за някои проблеми (Activity Selection, Fractional Knapsack), но **не гарантирано** за всички
- Смяна на монети показва как локално разумен избор може да пропусне глобалния оптимум
- Fractional Knapsack срещу 0/1 Knapsack е класически пример кога greedy замества DP и кога не
- Винаги проверявайте (или потърсете доказателство), че "greedy choice property" важи, преди да се доверите на жаден подход
