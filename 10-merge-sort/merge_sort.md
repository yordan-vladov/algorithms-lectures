## Мотивация

- При Quick Sort видяхме, че лош избор на pivot може да доведе до **O(n²)**
- Има ли алгоритъм с **гарантирана** O(n log n) сложност, независимо от входа?
- Да - **Merge Sort**

---

## Какво е Merge Sort?

- **Merge Sort** е алгоритъм за сортиране от типа "разделяй и владей" (divide and conquer)
- Основна идея:
    1. **Разделяме** масива на две половини
    2. Рекурсивно **сортираме** всяка половина
    3. **Сливаме** (merge) двете сортирани половини в един сортиран масив
- За разлика от Quick Sort - основната работа е в стъпката **след** рекурсията (сливането)

---

## Принцип на работа - "разделяй и владей"

```
Големият проблем:      Сортирай [10, 7, 8, 9, 1, 5]

Раздели:                на две половини: [10, 7, 8] и [9, 1, 5]

Владей:                  сортирай всяка половина рекурсивно

Съедини:                 слей двете сортирани половини в резултата
```

- Базов случай: масив с 0 или 1 елемент - вече е сортиран

---

## Разделяне (Divide)

```
                [10, 7, 8, 9, 1, 5]
                 /                \
         [10, 7, 8]              [9, 1, 5]
          /      \                /      \
       [10]    [7, 8]          [9]     [1, 5]
                /   \                    /   \
              [7]   [8]                [1]   [5]
```

- Делим, докато остане масив с 0 или 1 елемент (винаги сортиран)

---

## Сливане (Merge) - обратния път

```
[7]   [8]  →  merge  →  [7, 8]
[1]   [5]  →  merge  →  [1, 5]

[10]  [7,8]  →  merge  →  [7, 8, 10]
[9]   [1,5]  →  merge  →  [1, 5, 9]

[7,8,10]  [1,5,9]  →  merge  →  [1, 5, 7, 8, 9, 10]   ← сортиран!
```

- Резултатът "се качва" нагоре по дървото, сливайки се на всяко ниво

---

## Как работи `merge`?

- Взима **две вече сортирани** части и ги слива в една сортирана
- Използва два показалеца - по един за всяка част
- На всяка стъпка сравнява текущите елементи и взима по-малкия

```
left  = [7, 8]      i=0
right = [1, 5]      j=0

сравни left[0]=7 и right[0]=1 → 1 е по-малко → output: [1]         j++
сравни left[0]=7 и right[1]=5 → 5 е по-малко → output: [1, 5]      j++ (right свърши)
остана left → копирай директно                → output: [1, 5, 7, 8]
```

---

## Merge - алгоритъм

```
merge(arr, low, mid, high):
    left  = arr[low..mid]
    right = arr[mid+1..high]

    i = 0, j = 0, k = low

    докато i < len(left) и j < len(right):
        ако left[i] <= right[j]:
            arr[k] = left[i]; i++
        иначе:
            arr[k] = right[j]; j++
        k++

    копирай остатъка от left (ако има)
    копирай остатъка от right (ако има)
```

## Примерна имплементация - merge

```cpp
#include <iostream>
#include <vector>
using namespace std;

void merge(vector<int>& arr, int low, int mid, int high) {
    vector<int> left(arr.begin() + low, arr.begin() + mid + 1);
    vector<int> right(arr.begin() + mid + 1, arr.begin() + high + 1);

    int i = 0, j = 0, k = low;

    while (i < (int)left.size() && j < (int)right.size()) {
        if (left[i] <= right[j]) arr[k++] = left[i++];
        else                     arr[k++] = right[j++];
    }

    while (i < (int)left.size())  arr[k++] = left[i++];
    while (j < (int)right.size()) arr[k++] = right[j++];
}
```

## Примерна имплементация - рекурсията

```cpp
void mergeSort(vector<int>& arr, int low, int high) {
    if (low >= high) return;   // базов случай - 0 или 1 елемент

    int mid = low + (high - low) / 2;

    mergeSort(arr, low, mid);       // сортирай лявата половина
    mergeSort(arr, mid + 1, high);  // сортирай дясната половина
    merge(arr, low, mid, high);     // слей ги
}
```

*(пълният код е във `merge_sort.cpp`)*

## Пример за употреба

```cpp
int main() {
    vector<int> arr = {10, 7, 8, 9, 1, 5};

    mergeSort(arr, 0, (int)arr.size() - 1);

    for (int x : arr) cout << x << " ";
    // Изход: 1 5 7 8 9 10
}
```

## Сложност във времето

| Случай     | Сложност    | Бележка                                    |
| ---------- | ----------- | -------------------------------------------- |
| Най-добър  | O(n log n)  | Винаги делим на две равни половини          |
| Среден     | O(n log n)  | Няма зависимост от подредбата на входа       |
| Най-лош    | O(n log n)  | За разлика от Quick Sort - **гарантирана**   |

- Дълбочина на рекурсията: винаги `O(log n)`, тъй като делим точно наполовина
- На всяко ниво `merge` върши `O(n)` работа → общо `O(n log n)`

---

## Сложност по памет

- За разлика от Quick Sort - **не** е in-place
- `merge` създава временни масиви `left` и `right`

| Компонент          | Памет     |
| -------------------- | --------- |
| Временни масиви      | O(n)      |
| Call stack (рекурсия) | O(log n)  |
| Общо                 | **O(n)**  |

---

## Предимства на Merge Sort

- **Гарантирана O(n log n)** сложност - без влошен случай, за разлика от Quick Sort
- **Стабилен** - елементи с еднакви стойности запазват реда си (`left[i] <= right[j]`)
- Предвидим - работи еднакво добре независимо от подредбата на входа
- Естествено се **паралелизира** - двете половини са независими
- Идеален за **свързани списъци** и **външно сортиране** (данни, които не се събират в паметта)

---

## Недостатъци на Merge Sort

- Изисква **допълнителна памет** - O(n), за разлика от in-place Quick Sort
- По-бавен на практика от Quick Sort при масиви, събиращи се в кеша (повече копиране)
- По-сложна имплементация в сравнение с прости алгоритми (Bubble/Selection/Insertion)

---

## Merge Sort срещу Quick Sort

| Характеристика     | Merge Sort              | Quick Sort               |
| ------------------- | ------------------------- | -------------------------- |
| Най-лош случай      | O(n log n)                | O(n²)                      |
| Памет                | O(n)                      | O(log n) (in-place)        |
| Стабилност           | Да                        | Не                         |
| На практика          | Предвидим, малко по-бавен | Обикновено по-бърз          |
| Подходящ за          | Свързани списъци, външно сортиране | Масиви в паметта    |

---

## Кога да използваме Merge Sort?

- Когато е нужна **гарантирана** производителност - критични системи, реално време
- Когато е нужна **стабилност** на сортирането
- При сортиране на **свързани списъци** - `merge` не изисква индексиран достъп
- При **външно сортиране** - данни, по-големи от наличната памет (сливане на части от диска)
