## Какво е "разделяй и владей"?

Три стъпки за всеки проблем:

```
1. DIVIDE   (раздели)  → разбий проблема на по-малки подпроблеми от същия вид
2. CONQUER  (владей)   → реши подпроблемите рекурсивно (базов случай - тривиално решение)
3. COMBINE  (съедини)  → съедини решенията на подпроблемите в решение на целия проблем
```

- Забележете приликата с обикновената рекурсия - "разделяй и владей" **винаги** дели на **независими** подпроблеми

---

## Познати примери

| Алгоритъм    | Divide                          | Conquer                | Combine                          |
| ------------ | -------------------------------- | ----------------------- | ---------------------------------- |
| Binary Search | Раздели на ляво/дясно спрямо средата | Търси рекурсивно в едната половина | Няма - половината вече е отговорът |
| Merge Sort   | Раздели масива на две половини  | Сортирай всяка половина рекурсивно | `merge()` - слей двете сортирани половини |
| Quick Sort   | `partition()` - раздели около pivot | Сортирай двете части рекурсивно | Няма - масивът вече е на място |

- При Binary Search "владей" само едната половина - другата се изхвърля
- При Merge Sort работата е в **combine** (`merge`); при Quick Sort работата е в **divide** (`partition`)

## Нов пример - бързо степенуване

- Наивно: `power(x, n) = x * power(x, n-1)` → **O(n)** извиквания (виж `08-recursion`)
- С "разделяй и владей": делим степента наполовина всеки път

```
x^n =  (x^(n/2))^2         ако n е четно
x^n =  x * (x^(n/2))^2     ако n е нечетно

Пример: x^8
  x^8 = (x^4)^2
  x^4 = (x^2)^2
  x^2 = (x^1)^2
  x^1 = x * (x^0)^2 = x * 1
```

---

## Бързо степенуване - C++ код

```cpp
double fastPower(double x, int n) {
    if (n == 0) return 1;

    double half = fastPower(x, n / 2);

    if (n % 2 == 0)
        return half * half;
    else
        return x * half * half;
}
```

- Наивна версия: `O(n)` рекурсивни извиквания
- Fast power: `O(log n)` - **степента се дели наполовина** на всяка стъпка

```
power(2, 10):                fastPower(2, 10):
  11 извиквания               5 извиквания
  (10, 9, 8, ..., 1, 0)       (10 → 5 → 2 → 1 → 0)
```

## Нов пример - максимална сума на подмасив

**Задача:** намерете последователен подмасив с най-голяма сума

```
arr = [-2, 1, -3, 4, -1, 2, 1, -5, 4]

Отговор: [4, -1, 2, 1] → сума = 6
```

- Наивен подход: провери всички подмасиви → **O(n²)**
- "Разделяй и владей": максималният подмасив е в **лявата** половина, **дясната** половина, или **пресича средата**

```
              [-2, 1, -3, 4, -1, 2, 1, -5, 4]
                            mid
       ляво: [-2,1,-3,4,-1]  |  дясно: [2,1,-5,4]

Максимумът е един от трите случая:
  1. Максимален подмасив изцяло вляво
  2. Максимален подмасив изцяло вдясно
  3. Подмасив, който пресича средата (задължително включва mid и mid+1)
```

---

## Максимална сума при пресичане на средата

- Не можем просто да съединим двете половини на максималния подмасив вляво/вдясно - трябва отделна проверка
- Разширяваме **навън от средата** и в двете посоки, натрупвайки максимална сума

```cpp
int maxCrossingSum(vector<int>& arr, int low, int mid, int high) {
    int leftSum = INT_MIN, sum = 0;
    for (int i = mid; i >= low; i--) {
        sum += arr[i];
        leftSum = max(leftSum, sum);
    }

    int rightSum = INT_MIN;
    sum = 0;
    for (int i = mid + 1; i <= high; i++) {
        sum += arr[i];
        rightSum = max(rightSum, sum);
    }

    return leftSum + rightSum;
}
```

## Максимална сума - пълно решение

```cpp
int maxSubArraySum(vector<int>& arr, int low, int high) {
    if (low == high) return arr[low];  // базов случай - 1 елемент

    int mid = (low + high) / 2;

    int leftMax  = maxSubArraySum(arr, low, mid);
    int rightMax = maxSubArraySum(arr, mid + 1, high);
    int crossMax = maxCrossingSum(arr, low, mid, high);

    return max({leftMax, rightMax, crossMax});
}
```

- Сложност: `T(n) = 2T(n/2) + O(n)` → **O(n log n)**
- По-добро от наивното `O(n²)`, но не е оптималното - Kadane's algorithm (жаден подход) го решава за `O(n)`, виж `16-greedy-algorithms`

## Рекурентни отношения

- Всеки D&C алгоритъм има **рекурентно отношение**, описващо времето му

```
T(n) = a * T(n/b) + f(n)

  a    - брой подпроблеми
  n/b  - размер на всеки подпроблем
  f(n) - цена на divide + combine стъпките
```

| Алгоритъм       | Рекурентно отношение    | Сложност     |
| ---------------- | ------------------------- | ------------- |
| Binary Search    | `T(n) = T(n/2) + O(1)`    | O(log n)      |
| Merge Sort       | `T(n) = 2T(n/2) + O(n)`   | O(n log n)    |
| Quick Sort (среден) | `T(n) = 2T(n/2) + O(n)` | O(n log n)    |
| Fast Power       | `T(n) = T(n/2) + O(1)`    | O(log n)      |
| Max Subarray     | `T(n) = 2T(n/2) + O(n)`   | O(n log n)    |

---

## Master Theorem (интуитивно)

- Бърз начин да намерим сложността от `T(n) = a*T(n/b) + f(n)`, без да чертаем цялото дърво

```
Сравни f(n) с n^(log_b a):

  ако f(n) расте по-БАВНО   → T(n) = O(n^(log_b a))
  ако f(n) расте СЪЩО ТАКА  → T(n) = O(n^(log_b a) * log n)
  ако f(n) расте по-БЪРЗО   → T(n) = O(f(n))
```

```
Merge Sort: a=2, b=2, f(n)=O(n)
  n^(log_2 2) = n^1 = n
  f(n) = n  → расте "същото" → T(n) = O(n log n)  ✓
```

- Не е нужно да помните формулата - важно е да разбирате **защо** делението на подпроблеми дава `log n` фактор

---

## Кога да използваме "разделяй и владей"?

- Проблемът може да се раздели на **независими** подпроблеми от същия вид
- Подпроблемите **не се препокриват** (ако се препокриват - вижте `14-dynamic-programming`)
- Съединяването на решенията е **евтино** спрямо разделянето на проблема

---

## Предимства и недостатъци

| Предимства                                  | Недостатъци                                  |
| --------------------------------------------- | ----------------------------------------------- |
| Естествено паралелизируем (независими части) | Рекурсията ползва допълнителна памет (call stack) |
| Често дава `O(n log n)` вместо `O(n²)`       | Не помага, ако подпроблемите се препокриват     |
| Логиката е ясна и лесна за доказване          | Overhead от рекурсивните извиквания при малки n  |

## Обобщение

- "Разделяй и владей" = **divide** → **conquer** → **combine**
- Binary Search, Merge Sort и Quick Sort вече са примери за тази парадигма
- Fast power показва как делението на входа дава `O(log n)` вместо `O(n)`
- Max subarray показва трети случай - решение, което **пресича** границата на делението
- Master Theorem дава бърз начин за анализ на рекурентни отношения от вида `T(n) = aT(n/b) + f(n)`
