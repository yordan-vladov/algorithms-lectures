## Мотивация

- Как бихме сортирали масив по най-простия възможен начин?
- Идея: сравняваме **съседни** елементи и ги разменяме, ако не са в ред
- Повтаряме процеса, докато масивът стане сортиран

```
[5, 1, 4, 2, 8]
```

---

## Какво е Bubble Sort?

- **Bubble Sort** обхожда масива многократно
- При всяко обхождане сравнява **съседни двойки** елементи
- Ако елементите са в грешен ред - разменя ги
- Най-големият елемент "изплува" (bubble up) до края след всяко обхождане

---

## Принцип на работа - едно обхождане

```
[5, 1, 4, 2, 8]

сравни (5,1): 5>1 → размяна   → [1, 5, 4, 2, 8]
сравни (5,4): 5>4 → размяна   → [1, 4, 5, 2, 8]
сравни (5,2): 5>2 → размяна   → [1, 4, 2, 5, 8]
сравни (5,8): 5<8 → без размяна → [1, 4, 2, 5, 8]
```

- След първото обхождане, **най-големият** елемент (8) е на правилното си място

---

## Принцип на работа - следващи обхождания

```
Обхождане 1: [5, 1, 4, 2, 8] → [1, 4, 2, 5, 8]     (8 е на място)
Обхождане 2: [1, 4, 2, 5, 8] → [1, 2, 4, 5, 8]     (5 е на място)
Обхождане 3: [1, 2, 4, 5, 8] → [1, 2, 4, 5, 8]     (4 е на място)
```

- Всяко обхождане "избутва" следващия най-голям елемент на неговото място
- След `n - 1` обхождания масивът е сортиран

---

## Псевдокод

```
за i от 0 до n - 2:
    за j от 0 до n - 2 - i:
        ако arr[j] > arr[j + 1]:
            swap(arr[j], arr[j + 1])
```

- Външният цикъл - брой обхождания
- Вътрешният цикъл - сравнение на съседни елементи
- С всяко обхождане "изключваме" последните `i` елемента - те вече са наредени

---

## Примерна имплементация на C++

```cpp
#include <iostream>
#include <vector>
using namespace std;

void bubbleSort(vector<int>& arr) {
    int n = arr.size();

    for (int i = 0; i < n - 1; i++) {
        // последните i елемента вече са наредени
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);
            }
        }
    }
}
```

*(пълният код е във `bubble_sort.cpp`)*

## Оптимизация - ранно спиране

- Ако при цяло обхождане **няма нито една размяна** - масивът вече е сортиран
- Можем да спрем алгоритъма по-рано

```cpp
void bubbleSort(vector<int>& arr) {
    int n = arr.size();

    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;

        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);
                swapped = true;
            }
        }

        if (!swapped) break;   // масивът е сортиран - спираме
    }
}
```

## Пример за употреба

```cpp
int main() {
    vector<int> arr = {10, 7, 8, 9, 1, 5};

    bubbleSort(arr);

    for (int x : arr) cout << x << " ";
    // Изход: 1 5 7 8 9 10
}
```

## Сложност във времето

| Случай     | Сложност | Кога се случва                       |
| ---------- | -------- | -------------------------------------- |
| Най-добър  | O(n)     | Масивът вече е сортиран (с оптимизация) |
| Среден     | O(n²)    | Случайно наредени елементи             |
| Най-лош    | O(n²)    | Масивът е сортиран в обратен ред       |

- Без оптимизацията за ранно спиране - винаги O(n²)

---

## Сложност по памет

- Сортира **на място** (in-place) - не се нуждае от допълнителен масив
- Памет: **O(1)**

---

## Предимства на Bubble Sort

- **Много прост** за разбиране и имплементация
- **In-place** - не изисква допълнителна памет
- **Стабилен** - елементи с еднакви стойности запазват реда си
- С оптимизация - **O(n)** при почти сортирани данни

---

## Недостатъци на Bubble Sort

- **Бавен** - O(n²) в среден и най-лош случай
- Непрактичен за големи масиви
- Много повече размени в сравнение с Selection Sort
- Рядко се използва на практика извън учебни цели

---

## Кога да използваме Bubble Sort?

- Основно за **учебни цели** - лесен за разбиране принцип на сортиране
- При **много малки** или **почти сортирани** масиви
- Никога при големи набори от данни - има много по-ефективни алгоритми

## Обобщение

- Bubble Sort сравнява и разменя **съседни** елементи многократно
- Най-големите елементи "изплуват" до края при всяко обхождане
- Сложност **O(n²)** в среден и най-лош случай, **O(n)** в най-добрия (с оптимизация)
- Прост, стабилен, in-place, но неефективен за големи данни
