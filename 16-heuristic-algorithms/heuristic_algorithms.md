# Евристични алгоритми (Heuristic Algorithms)

---

## Какво ще научим днес?

- Какво е "трудна" (NP-трудна) задача и защо не винаги можем да намерим точен отговор бързо
- Какво е евристика и с какво се различава от точен алгоритъм
- Пример: Търговски пътник (TSP) и евристиката "най-близкия съсед"
- Пример: Hill Climbing (изкачване на хълм) - локално търсене
- Увод в A* търсене - евристика, водеща търсенето
- Кога да жертваме точност за скорост

---

## Мотивация

- Досега всички наши алгоритми (Quick Sort, Dijkstra-подобни BFS, DP, Greedy) намират **точен, доказано правилен** отговор
- Съществуват задачи, за които **не познаваме бърз точен алгоритъм** - най-добрите известни решения растат експоненциално

```
Проблем: Търговски пътник (TSP)
  Посетете N града точно веднъж и се върнете в началото - намерете НАЙ-КЪСИЯ маршрут

  Брой възможни маршрути: (N-1)! / 2
  N=10  →     181 440 маршрута  (още обходимо)
  N=20  →  60 822 550 204 416 000 маршрута (необходимо е ~2000 години на суперкомпютър)
```

- За такива задачи разчитаме на **евристики** - алгоритми, които намират **добро**, но не гарантирано оптимално решение, бързо

---

## NP-трудни задачи (накратко)

- Някои проблеми нямат познат алгоритъм, работещ в полиномиално време (`O(nᵏ)`) за точно решение
- Наричат се **NP-трудни** - примери: Търговски пътник, Раница (в общия случай), оцветяване на граф с минимален брой цветове
- За разлика от Knapsack (0/1), който решихме с DP за `O(n·W)` - TSP няма познато полиномиално решение

```
P         - решими бързо (полиномиално време): Sorting, Binary Search, Dijkstra
NP-трудни - точно решение е бавно (експоненциално): TSP, оптимално оцветяване на граф
```

- За NP-трудни задачи с голям вход - **точно решение е непрактично**, затова използваме евристики

---

## Какво е евристика?

- Практическо правило или стратегия, която дава **добро** решение бързо, без гаранция за оптималност

```
Точен алгоритъм:   винаги намира НАЙ-ДОБРОТО решение, но може да е бавен
Евристика:         намира ДОБРО решение бързо, без гаранция, че е най-доброто
```

- Компромис: **скорост срещу оптималност**
- Използваме евристики, когато точното решение е непрактично бавно за размера на входа

## Пример 1 - TSP с "най-близкия съсед" (Nearest Neighbor)

**Стратегия:** тръгни от произволен град; на всяка стъпка отиди в **най-близкия непосетен** град

```cpp
vector<int> nearestNeighborTSP(vector<vector<double>>& dist, int start) {
    int n = dist.size();
    vector<bool> visited(n, false);
    vector<int> route;

    int current = start;
    visited[current] = true;
    route.push_back(current);

    for (int step = 1; step < n; step++) {
        int nearest = -1;
        double nearestDist = 1e18;

        for (int city = 0; city < n; city++) {
            if (!visited[city] && dist[current][city] < nearestDist) {
                nearest = city;
                nearestDist = dist[current][city];
            }
        }

        visited[nearest] = true;
        route.push_back(nearest);
        current = nearest;
    }

    return route;
}
```

---

## Nearest Neighbor - визуализация

```
Градове:  A(0,0)  B(1,5)  C(5,2)  D(6,6)  E(8,3)

Старт от A:
  Най-близък до A (непосетен) → B (разстояние ~5.10, най-малко от B,C,D,E)
  Най-близък до B (непосетен) → C (разстояние ~5.00, по-малко от D~5.10 и E~7.28)
  Най-близък до C (непосетен) → E (разстояние ~3.16, по-малко от D~4.12)
  Остава D

Маршрут: A → B → C → E → D → (обратно в A)
Обща дължина: ~25.35
```

- **Проблем:** локално разумният избор може да "остави" далечен град за накрая, оскъпявайки целия маршрут
- Nearest Neighbor обикновено дава маршрут **до ~25% по-дълъг** от оптималния - но за милисекунди, вместо години

## Пример 2 - Hill Climbing (изкачване на хълм)

- Общ метод за локално търсене: тръгни от произволно решение, **премести се** към по-добър съсед, спри когато няма по-добър съсед

```
Общ шаблон:

current = произволно начално решение
докато има по-добър съсед на current:
    current = най-добрият съсед
върни current
```

```
Пейзаж на решенията (стойност на решението):

        ▲
   4  ┌─┘ └┐         ┌──┐
   3 ┌┘    └┐      ┌─┘  └┐
   2 │      └┐   ┌─┘     └─
   1 │       └───┘
     └──────────────────────►
       локален максимум    глобален максимум

Ако тръгнем от лявата "могила" - hill climbing спира на ЛОКАЛНИЯ максимум,
без да разбере, че съществува по-добро решение по-нататък!
```

---

## Проблемът с локалните максимуми

- Hill climbing е "лаком" по същия начин като greedy алгоритмите от `15-greedy-algorithms` - но тук **няма доказателство**, че локалният избор води до глобален оптимум
- Разлики с DP/Greedy, които видяхме досега: тук **съзнателно приемаме**, че решението може да не е оптимално

**Общи трикове за избягване на локални максимуми:**

```
Random restarts       - пробвай hill climbing от няколко случайни стартови точки
Simulated annealing   - понякога приемай ПО-ЛОШ съсед, за да "избягаш" от локален максимум
                         (вероятността намалява постепенно, както при изстиващ метал)
```

## Пример 3 - A* търсене (кратко въведение)

- В `17-array-list`...`22-graphs` учихме BFS - намира най-къс път, но обхожда "слепешката" във всички посоки
- **A\*** използва **евристична функция** `h(n)` - оценка "колко далеч е още целта" - за да **насочи** търсенето

```
Избираме следващия връх за обхождане по:
  f(n) = g(n) + h(n)

  g(n) = реалната цена от старта до n (каквото знаем сигурно)
  h(n) = евристична оценка от n до целта (напр. права линия на карта)
```

```
BFS:  обхожда във всички посоки еднакво - "слепешката"

      ●●●●●●●
      ●●[S]●●●●●●●●[G]
      ●●●●●●●

A*:   насочено към целта чрез h(n) - обхожда МНОГО по-малко върхове

      [S]────────────►[G]
```

- Ако `h(n)` никога не надценява реалната цена ("admissible") - A* гарантирано намира оптималния път, но обикновено много по-бързо от BFS на практика
- Пример за `h(n)` в мрежа от квадратчета: Manhattan distance `|x1-x2| + |y1-y2|`

## Евристика срещу точен алгоритъм

| Характеристика         | Точен алгоритъм (DP, Greedy с доказателство, BFS) | Евристика (Nearest Neighbor, Hill Climbing) |
| ------------------------ | ------------------------------------------------------ | ------------------------------------------------ |
| Гаранция за оптималност  | Да                                                      | Не                                                |
| Скорост при голям вход   | Може да е непрактично бавен (NP-трудни задачи)         | Бърз, дори за много голям вход                    |
| Кога се използва         | Когато точността е критична и входът е управляем       | Когато точното решение е непостижимо във времето  |

---

## Кога да използваме евристики?

- Проблемът е **NP-труден** - точно решение расте експоненциално с размера на входа
- Входът е твърде голям за точен алгоритъм в разумно време
- "Достатъчно добро" решение е приемливо (напр. маршрут само с няколко % по-дълъг от оптималния)

```
Реални приложения:
  GPS навигация     - A* / Dijkstra с евристики за милиони пътни възли
  Опаковане на стоки - евристики за подреждане на кутии в контейнер
  Машинно обучение  - gradient descent е форма на hill climbing
  Игри (шах, го)     - евристични функции за оценка на позиция
```

## Обобщение

- NP-трудните задачи (TSP и др.) нямат познат бърз точен алгоритъм - евристиките са практичната алтернатива
- Евристика = бързо **добро** решение без гаранция за оптималност
- Nearest Neighbor - жадна евристика за TSP; проста, но може да пропусне оптимума
- Hill Climbing може да заседне в локален максимум - random restarts и simulated annealing помагат
- A* показва как евристична функция може да насочи търсенето и да ускори точен резултат, а не само приблизителен
- Изборът между точен алгоритъм и евристика е компромис между **гарантирана коректност** и **практическа скорост**
