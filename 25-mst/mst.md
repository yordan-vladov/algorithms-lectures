## Мотивация

- Досега графите ни бяха **непретеглени** - всяко ребро "тежеше" еднакво
- Много реални мрежи имат **тегла**: разстояние, цена, време

```
Проблем: свържи N селища с пътища, така че всички да са свързани
         и общата дължина на построените пътища да е минимална

  Граф с тегла → трябва ни алгоритъм, който намира
                  най-евтината комбинация от ребра
```

- Претеглен граф - на всяко ребро съответства число (**тегло**)

---

## Представяне на претеглен граф

```cpp
#include <vector>
struct Edge { int to, weight; };

const int N = 5;
vector<Edge> adj[N];

void addEdge(int u, int v, int w) {
    adj[u].push_back({v, w});
    adj[v].push_back({u, w});  // за ненасочен граф
}
```

- Алтернатива: **матрица на съседство**, където `graph[u][v]` пази теглото (0 или `INF`, ако няма ребро)

---

## Какво е минимално покриващо дърво (MST)?

- **Покриващо дърво (spanning tree)** на свързан граф - подмножество от ребра, което свързва **всички** върхове, без цикли
- Има точно **V - 1** ребра (както всяко дърво)
- **Минимално покриващо дърво (MST)** - покриващото дърво с **най-малка сума от теглата**

```
Граф (5 върха, претеглен):
  0—1(4), 0—2(1), 1—2(2), 1—3(5), 2—3(8), 2—4(10), 3—4(2)

MST (тегло общо 10):
  0—2(1), 1—2(2), 1—3(5), 3—4(2)
```

- MST съществува само за **свързан** граф (иначе - минимална покриваща гора)

---

## Алгоритъм на Prim - идея

- Расте **едно дърво**, като на всяка стъпка добавя **най-евтиното ребро**, излизащо от вече построеното дърво към нов връх
- Прилича на BFS/Dijkstra по структура, но избира ребро с **минимално тегло**, не по ред на откриване

```
Стъпка 1: дърво = {0}
Стъпка 2: най-евтино ребро от {0} навън е 0—2(1) → дърво = {0, 2}
Стъпка 3: най-евтино ребро от {0,2} навън е 1—2(2) → дърво = {0, 1, 2}
Стъпка 4: най-евтино ребро навън е 1—3(5) → дърво = {0, 1, 2, 3}
Стъпка 5: най-евтино ребро навън е 3—4(2) → дърво = {0, 1, 2, 3, 4}

MST: 0—2(1), 1—2(2), 1—3(5), 3—4(2)   Общо тегло: 10
```

## Имплементация на Prim (O(V²))

```cpp
#include <vector>
#include <climits>
using namespace std;
const int INF = INT_MAX;

int primMST(int n, vector<vector<int>>& graph) {
    vector<int> dist(n, INF);
    vector<bool> inMST(n, false);
    dist[0] = 0;

    int totalWeight = 0;
    for (int i = 0; i < n; i++) {
        int u = -1;
        for (int v = 0; v < n; v++)               // намери най-евтиния
            if (!inMST[v] && (u == -1 || dist[v] < dist[u]))
                u = v;

        inMST[u] = true;
        totalWeight += dist[u];

        for (int v = 0; v < n; v++)                // обнови съседите
            if (!inMST[v] && graph[u][v] && graph[u][v] < dist[v])
                dist[v] = graph[u][v];
    }
    return totalWeight;
}
```

- `dist[v]` = теглото на най-евтиното ребро, свързващо `v` с вече построеното дърво
- Тук търсим минимума с цикъл (O(V) на стъпка) - по-късно (лекция за heap) ще видим как `priority_queue` ускорява това до O(E log V)

## Union-Find (Disjoint Set) - кратко въведение

- Структура от данни, която пази **непресичащи се множества** и отговаря бързо на два въпроса:
    - `find(x)` - в кое множество е `x`?
    - `unite(a, b)` - обедини множествата на `a` и `b`
- На Kruskal му трябва, за да провери бързо дали добавянето на ребро **създава цикъл** (двата върха вече са в едно и също множество)

```cpp
vector<int> parent;

int find(int x) {
    if (parent[x] != x)
        parent[x] = find(parent[x]);  // компресия на пътя
    return parent[x];
}

void unite(int a, int b) {
    parent[find(a)] = find(b);
}
```

- Всеки връх започва като собствен родител: `parent[i] = i`

---

## Алгоритъм на Kruskal - идея

- **Жаден** алгоритъм: сортира **всички ребра** по тегло и добавя най-евтините едно по едно
- Добавя ребро, само ако не създава цикъл (проверка с Union-Find)

```
Сортирани ребра: 0—2(1), 1—2(2), 3—4(2), 0—1(4), 1—3(5), 2—3(8), 2—4(10)

0—2(1): добави  → {0,2}
1—2(2): добави  → {0,1,2}
3—4(2): добави  → {0,1,2} и {3,4}
0—1(4): пропусни (0 и 1 вече са свързани - цикъл)
1—3(5): добави  → {0,1,2,3,4}  (V-1 = 4 ребра - край)

MST: 0—2(1), 1—2(2), 3—4(2), 1—3(5)   Общо тегло: 10
```

## Имплементация на Kruskal

```cpp
#include <algorithm>
#include <vector>
using namespace std;

struct Edge { int u, v, w; };

int kruskalMST(int n, vector<Edge>& edges) {
    sort(edges.begin(), edges.end(),
         [](Edge& a, Edge& b) { return a.w < b.w; });

    parent.resize(n);
    for (int i = 0; i < n; i++) parent[i] = i;

    int totalWeight = 0, edgesUsed = 0;
    for (Edge& e : edges) {
        if (find(e.u) != find(e.v)) {   // не създава цикъл
            unite(e.u, e.v);
            totalWeight += e.w;
            if (++edgesUsed == n - 1) break;
        }
    }
    return totalWeight;
}
```

- Сложност: **O(E log E)** заради сортирането на ребрата (Union-Find операциите са почти O(1))

## Prim срещу Kruskal

| Характеристика          | Prim                              | Kruskal                          |
| ------------------------ | ---------------------------------- | ---------------------------------- |
| Стратегия                | Разраства **едно дърво**           | Добавя най-евтините ребра **глобално** |
| Структура от данни       | Масив с `dist[]` (или `priority_queue`) | Сортиране + Union-Find        |
| Сложност                 | O(V²) (или O(E log V) с heap)      | O(E log E)                        |
| Предпочитан при          | Плътен граф (матрица на съседство) | Рядък граф (списък от ребра)      |
| Представяне на графа     | Матрица или списък на съседство    | Списък от ребра                   |

- И двата **винаги намират валидно MST**, ако графът е свързан - разликата е в стратегията и представянето

## Реални приложения на MST

- **Проектиране на мрежи** - минимална дължина кабели/тръби, свързващи всички сгради
- **Клъстеризация** - премахване на най-скъпите ребра от MST групира близки точки
- **Схеми на платки** - минимална дължина проводници, свързващи компонентите
- **Приближени решения на TSP** - MST дава долна граница и основа за евристики (вижте лекцията за евристични алгоритми)

## Обобщение

- **MST** - покриващо дърво с минимална сума от теглата на ребрата
- **Prim** разраства едно дърво, избирайки на всяка стъпка най-евтиното ребро навън - O(V²) без heap
- **Kruskal** сортира всички ребра и добавя най-евтините, проверявайки цикли с **Union-Find** - O(E log E)
- Изборът зависи от гъстотата на графа: Prim за плътни, Kruskal за редки графи
- В следващата лекция: **алгоритъм на Dijkstra** - най-къс път в претеглен граф от един връх до всички останали
