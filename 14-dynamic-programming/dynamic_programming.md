# Динамично програмиране (Dynamic Programming)

---

## Какво ще научим днес?

- Защо наивната рекурсия понякога е бавна - препокриващи се подпроблеми
- Memoization (top-down) срещу Tabulation (bottom-up)
- Пример: Fibonacci - от експоненциално до линейно
- Пример: 0/1 Раница (Knapsack)
- Пример: Longest Common Subsequence (LCS)
- Кога проблем "мирише" на динамично програмиране

---

## Мотивация

- В `08-recursion` видяхме наивен Fibonacci:

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

- Отбелязахме проблем: "Много повтарящи се изчисления → бавен алгоритъм"

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) ...
│   │   └── fib(1)
│   └── fib(2)          ← пресмятаме fib(2) ПАК
│       ├── fib(1)
│       └── fib(0)
└── fib(3)               ← пресмятаме fib(3) ПАК (цяло поддърво!)
    ├── fib(2) ...
    └── fib(1)
```

- `fib(2)` се пресмята многократно - **едни и същи подпроблеми се решават отново и отново**

---

## Какво е динамично програмиране?

- Техника за проблеми с две свойства:

```
1. Overlapping subproblems (препокриващи се подпроблеми)
   → едни и същи по-малки задачи се срещат многократно

2. Optimal substructure (оптимална подструктура)
   → решението на проблема се строи от оптималните решения на подпроблемите
```

- Идея: **реши всеки подпроблем само веднъж**, запази резултата, използвай го при нужда повторно

```
Наивна рекурсия:  fib(5) прави 15 извиквания
Динамично прогр.: fib(5) прави 6 изчисления (всяко число веднъж)
```

---

## Разлика с "разделяй и владей"

| Характеристика       | Разделяй и владей          | Динамично програмиране        |
| ---------------------- | ----------------------------- | -------------------------------- |
| Подпроблеми           | Независими, не се препокриват | Препокриват се                  |
| Пример                 | Merge Sort, Quick Sort        | Fibonacci, Knapsack, LCS         |
| Стратегия              | Раздели → реши → съедини      | Реши веднъж → запази → преизползвай |

- И двете разчитат на рекурсивна структура, но DP добавя **памет** (кеширане) заради препокриването

---

## Memoization (top-down)

- Взимаме наивната рекурсия и добавяме **кеш** (обикновено масив или `unordered_map`)
- Преди да пресметнем - проверяваме дали вече имаме отговора

```cpp
unordered_map<int, long long> memo;

long long fibMemo(int n) {
    if (n <= 1) return n;

    if (memo.count(n)) return memo[n];   // вече е пресметнато - върни го

    memo[n] = fibMemo(n - 1) + fibMemo(n - 2);
    return memo[n];
}
```

```
fib(5) с memoization:

fib(5) → fib(4) → fib(3) → fib(2) → fib(1)=1
                                   → fib(0)=0
                          → fib(1) [в кеша] = 1
                 → fib(2) [в кеша]
        → fib(3) [в кеша]

Всяко число се пресмята ТОЧНО веднъж
```

## Tabulation (bottom-up)

- Вместо рекурсия - строим отговора **отдолу нагоре**, с цикъл и таблица

```cpp
long long fibTab(int n) {
    if (n <= 1) return n;

    vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; i++)
        dp[i] = dp[i - 1] + dp[i - 2];

    return dp[n];
}
```

```
dp[0]=0  dp[1]=1  dp[2]=1  dp[3]=2  dp[4]=3  dp[5]=5
          ↑        строим последователно, всяка клетка използва предишните
```

- Няма рекурсия → няма риск от stack overflow, обикновено по-бърз (без overhead от извиквания)

---

## Memoization срещу Tabulation

| Характеристика     | Memoization (top-down)         | Tabulation (bottom-up)       |
| --------------------- | --------------------------------- | -------------------------------- |
| Стил                 | Рекурсия + кеш                    | Цикъл + таблица                  |
| Ред на пресмятане     | Както го изисква рекурсията       | Систематично, от малко към голямо |
| Пресмята ли излишно?  | Не - само нужните подпроблеми     | Пресмята всички до n              |
| Памет                 | Кеш + call stack                  | Само таблицата                    |
| По-лесно за писане    | Обикновено да (близо до наивната рекурсия) | Изисква да мислим за реда  |

## Пример - 0/1 Раница (Knapsack)

**Задача:** имаме предмети с тегло и стойност; раница с максимален капацитет `W`. Изберете предмети (всеки или изцяло, или изобщо) с максимална обща стойност, без да надвишите `W`.

```
Предмети:  тегло: [2, 3, 4, 5]   стойност: [3, 4, 5, 6]
Капацитет: W = 5

Възможности:
  {предмет0, предмет1} → тегло 5, стойност 7   ← оптимално
  {предмет3}            → тегло 5, стойност 6
```

---

## Knapsack - структура на подпроблема

```
dp[i][w] = максималната стойност, използвайки първите i предмета,
           с капацитет w

За всеки предмет i избираме:
  - НЕ го вземаме:  dp[i][w] = dp[i-1][w]
  - Вземаме го (ако тежи <= w):  dp[i][w] = value[i] + dp[i-1][w - weight[i]]

dp[i][w] = max(двата варианта)
```

```cpp
int knapsack(vector<int>& weight, vector<int>& value, int W) {
    int n = weight.size();
    vector<vector<int>> dp(n + 1, vector<int>(W + 1, 0));

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= W; w++) {
            dp[i][w] = dp[i - 1][w];  // не взимаме предмет i-1

            if (weight[i - 1] <= w)
                dp[i][w] = max(dp[i][w], value[i - 1] + dp[i - 1][w - weight[i - 1]]);
        }
    }

    return dp[n][W];
}
```

---

## Knapsack - визуализация на таблицата

```
weight = [2,3,4,5]  value = [3,4,5,6]  W=5

        w=0  1  2  3  4  5
i=0      0   0  0  0  0  0
i=1(тегло2,ст.3)  0   0  3  3  3  3
i=2(тегло3,ст.4)  0   0  3  4  4  7
i=3(тегло4,ст.5)  0   0  3  4  5  7
i=4(тегло5,ст.6)  0   0  3  4  5  7

dp[4][5] = 7  ← оптимален отговор
```

- Всяка клетка се пресмята от **горния ред** (без предмета) и клетка **вляво нагоре** (с предмета)

## Пример - Longest Common Subsequence (LCS)

**Задача:** намерете най-дългата обща подредица (не задължително последователна) на два низа

```
text1 = "ABCBDAB"
text2 = "BDCABA"

LCS = "BCBA"  (дължина 4)
```

```cpp
int lcs(string a, string b) {
    int n = a.size(), m = b.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));

    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (a[i - 1] == b[j - 1])
                dp[i][j] = dp[i - 1][j - 1] + 1;
            else
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
        }
    }

    return dp[n][m];
}
```

- Ако символите съвпадат → удължаваме предишната обща подредица
- Ако не съвпадат → вземаме по-добрия резултат, като пропуснем символ от единия низ

---

## Сложност

| Задача              | Наивна рекурсия | С динамично програмиране |
| --------------------- | ------------------ | --------------------------- |
| Fibonacci(n)          | O(2ⁿ)              | O(n)                        |
| 0/1 Knapsack (n предмета, капацитет W) | O(2ⁿ) | O(n · W)              |
| LCS (низове с дължина n, m)            | O(2ⁿ⁺ᵐ)  | O(n · m)             |

- DP превръща експоненциална сложност в полиномиална, като жертва памет за таблицата

---

## Кога проблем "мирише" на DP?

- Задачата пита за **максимум/минимум/брой начини**
- Решението на проблема с вход `n` зависи от решения на **по-малки** версии на същия проблем
- Наивната рекурсия прави **едни и същи** извиквания многократно

```
Сигнали за DP:
  "Намерете максималната/минималната ..."
  "По колко начина можем ..."
  "Възможно ли е да постигнем ... с дадени ограничения"
```

## Обобщение

- DP решава проблеми с **препокриващи се подпроблеми** и **оптимална подструктура**
- Memoization (top-down) = рекурсия + кеш; Tabulation (bottom-up) = цикъл + таблица
- Fibonacci: от `O(2ⁿ)` до `O(n)`
- Knapsack и LCS показват типична 2D DP таблица, строена ред по ред
- Ключов сигнал: наивната рекурсия решава **едни и същи подпроблеми многократно**
